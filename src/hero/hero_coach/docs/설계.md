# hero_coach 설계

`hero_hud` 가 README 에 "미구현"으로 비워 둔 자리다. CARLA + monoscale 스택의
출력을 HUD 표시 계약(`hero_hud/msg`)으로 바꾼다. **HUD 는 건드리지 않는다** —
HUD 는 Autoware 없이 빌드되어야 하고(Orin), 이 패키지만 Autoware 에 의존한다.

## 범위

실시간 CARLA, 사람이 키보드로 운전, 목표는 RViz 2D Goal Pose.

| HUD 입력 | 채우는 것 | 출처 |
|---|---|---|
| `/hero/vehicle_state` | 기어·속도·조향륜각·요레이트 | CARLA 브리지 `/vehicle/status/*` |
| `/hero/scene_overlay` `obstacles` | 자차 주변 점유 셀 | monoscale 격자 |
| `/hero/scene_overlay` `ideal` · `advised_gear` | 지금 달리는 구간과 그 방향 | Autoware A* (legacy `parking_planner` 이식) |
| `/hero/scene_overlay` `health` | `odometry`, `occupancy` 신선도 | 수신 시각 |

비워 두는 것: 주변광(HUD 가 밝음을 가정한다), 표지판, 신호, 코칭 문구 — 상류가 없다.
없는 상류를 지어내지 않는다.

## 노드

```
/vehicle/status/{velocity,steering,gear}_status
        └→ vehicle_state_adapter ─→ /hero/vehicle_state
/perception/occupancy_grid_map ─┬→ parking_planner ─→ /hero_coach/trajectory (map)
/localization/kinematic_state ──┤        ↑ /goal_pose (RViz)
                                └→ coach_node ─→ /hero/scene_overlay (10 Hz)
```

- **`vehicle_state_adapter`** 는 따로 산다. 항상 살아 있어야 하는 CAN 계층을 가장
  잘 죽는 노드(A*, 격자)에 묶지 않는다 — `hero_hud` 의 원칙 그대로다.
- **`parking_planner`** 는 A* 가 수 초 걸릴 수 있어서 `coach_node` 와 분리한다.
  계획하는 동안에도 장면은 10 Hz 로 나가야 한다.

## 결정

**미지 셀을 계획기에서는 free 로 본다.** Autoware `setMap` 은 `cost < 0` 을 장애물로
친다. 카메라 격자는 대부분이 미지이고, monoscale 은 실제로 매핑한 창만 발행하므로
목표가 창 밖이면 계획이 원천적으로 실패한다. 계획기는 자차와 목표를 감싸는 고정 창을
새로 만들어 알려진 셀만 붙여 넣는다. 낙관적이지만 사람이 운전하는 코칭이고,
막힌 것이 새로 보이면 재계획한다.

**표시에서는 미지 셀을 그리지 않는다.** HUD 의 "모르면 안 그린다".

**자차 발자국 안의 점유는 버린다.** 남기면 코리도 표본 0 에 영구 정지선이 선다.

**HUD 에는 지금 구간만 보낸다.** 전후진 전환점까지다. 전체 계획을 보내면 뒤로 꺾이는
부분이 목표 호의 곡률을 오염시킨다. 구간 끝(0.5 m)에 닿으면 다음 구간으로 넘어간다.
좌표는 자차에서 시작하고 진행 방향으로 뻗는다 — 후진 구간은 base_link 뒤쪽이다.

**`advised_gear` 는 필요한 기어를 늘 보낸다.** 현재 기어와 비교해 점멸할지는 HUD 가
정한다. 마지막 구간 끝이면 P.

**재계획**은 목표 수신, 경로가 새 점유에 막힘, 경로 이탈 1.0 m 초과일 때. 쿨다운 1 s.
계획 실패는 빈 궤적을 발행해 HUD 의 목표선을 거둔다 — 낡은 목표선은 없는 것보다 나쁘다.
**새 목표를 받는 즉시**도 빈 궤적을 낸다. 안 그러면 코치가 이미 끝난 이전 궤적을 보고
새 목표를 받자마자 P 를 권고한다(CARLA 에서 실제로 그랬다).

**막힘은 A* 와 같은 차체 상자로 본다.** legacy 는 후륜축 중심 원(반폭 + 0.1 m)으로 봤다.
합성 장면에서 A* 가 상자 여유 0.11 m 로 통과시킨 경로를 원이 1.10 m 에서 막힘으로 읽어
쿨다운마다 재계획했다. 보간점의 방향각도 보간한다 — 앞 점 방향을 그대로 쓰면 1 m 호에서
차 앞끝이 0.7 m 옆으로 간다.

**오도메트리 신선도는 시간이 아니라 pose 없이 달린 거리로 잰다.** monoscale 은 누적
시차로 풀어서 1.5 m/s 에 8.7 Hz, 정지 시 0.5 Hz 다. 고정 0.5 s 는 멈출 때마다, 속도별
시간은 오래된 정지 pose 에서 출발하는 순간마다 인지를 철회했다(HUD 줄무늬 깜빡임).
CAN 속도를 적분해 0.6 m(풀이 간격 ~0.2 m 의 3배)를 넘거나 5 s 를 넘으면 끊긴 것이다.
CAN 이 없으면 0.5 s 만 믿는다.

**조향각은 Ackermann 으로 되돌린다.** 브리지는 왼쪽 앞바퀴 하나의 각도를 보고한다.
CARLA 실측: steer +1 → +1.222 rad(안쪽 70°), −1 → −0.815 rad(바깥쪽 46.7°). 축거 2.819,
윤거 1.629 로 둘 다 자전거 등가 0.9925 rad 가 된다. 보정 없이는 좌회전 코리도가 과장된다
(steer 0.5 에서 13%). 계획기 최대 조향각도 이 값이다.

**말은 상태가 바뀌는 순간만 한다.** HUD 에서 글자를 걷어낸 뒤(저시력 사용자 피드백)
기어와 정지는 화면의 도형과 음성이 나눠 맡는다. 되풀이는 지금 막혀 있는 동안만이고
도착 권고는 한 번이다 — 계속 말하면 정작 급할 때 밀린다. 가는 쪽만 본다: 뒤에 있는
장애물로 "정지"를 외치면 주차장에서 내내 말하게 된다.

**문구는 미리 굽는다.** piper 합성은 한 마디에 수백 ms 다. 말할 때마다 치르면 "정지"가
가장 급할 때 가장 늦는다. 시작할 때 WAV 로 구워 캐시에 두고, 말할 때는 재생만 한다.
piper 나 모델이 없으면 한 번 경고하고 조용히 지낸다 — 음성이 없다고 화면을 멈출
이유가 없다.

**`map` 과 `odom` 을 같게 본다.** monoscale 은 `map→odom` 을 항등으로 내고 격자는
`map`, 오도메트리는 `odom` 이다. 둘이 어긋나기 시작하면 이 가정이 먼저 깨진다.

## 차량 제원

CARLA 차량은 Prius 다. 축거 2.819 m · 앞 윤거 1.629 m(`get_physics_control`), 후륜축 기준
전단 3.656 m · 후단 −0.858 m(`sensor_kit_calibration.yaml`), 반폭 1.0 m(CARLA 박스, 미러 포함). HUD 도 같은 축거로
덮어쓴다(`config/hud_carla.yaml`). 실차 IONIQ 로 가면 이 파일 하나를 바꾼다.

## 검증

- 순수 계산은 ROS 없이 `pytest` (48개).
- 통합은 CARLA 실시간에서 HUD 메시지만 보고 운전하는 시험 운전자로 했다. 결과는 README.

## 종료

`carla_live.sh` 는 launch 를 job control(`set -m`)로 자기 프로세스 그룹에 띄우고, 정리할 때
launch 에 SIGINT → 15 s 뒤 그룹 TERM → KILL 로 올린다. 둘 다 실측한 함정이다: job control
없이 `&` 로 띄우면 SIGINT 가 무시된 채 시작되고, `ros2 launch` 는 SIGTERM 에 자식을 두고
즉시 죽어 노드 7개가 고아로 남았다.

## 알려진 한계

- 격자 품질이 그대로 화면 품질이다. monoscale 의 연석 오판(G2)·오검출(G4)은
  유령 정지선과 계획 실패로 나타난다.
- A* 파라미터는 legacy(`isaac_autoware_bridge`) 값이고 CARLA 에서 조정하지 않았다.
- 주차 결과의 위치는 monoscale 추정이다. CARLA 참값과 대조하지 않았다.
